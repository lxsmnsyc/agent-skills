# Steps for each kind of product

Find the kind that fits the product and follow its steps on top of the rules in SKILL.md. A product can fit more than one kind, such as a library with a hosted service. Then follow the steps of each.

## Library, framework or SDK

The visitor is a developer deciding whether to add a dependency.

1. **Demo**: the install command, the smallest working code, and its output next to it. Make the code editable in a playground when the library runs in the browser.
2. **Differentiator**: compare with the main alternatives on what developers weigh: bundle size, speed, API size, types, runtime support. Show a short code comparison of the same task in both.
3. **Playful UI**: let the visitor change the code or an input and see the output update live. For a UI library, render real components the visitor can use.
4. **Proof**: npm weekly downloads, GitHub stars, dependents, and projects or companies that use it. Fetch the numbers at build time or on load.
5. **Objections**: license, bundle size, supported runtimes and framework versions, TypeScript support, maturity (version, release cadence, test coverage).
6. **CTA**: "Get started", linking to the docs page with the install step. Put the copyable install command in the hero.

## CLI or developer tool

The visitor wants to know what running it feels like.

1. **Demo**: a terminal recording or an animated terminal that types a command and shows its real output. Keep it under 20 seconds and loop it.
2. **Differentiator**: time saved or steps removed, compared with the usual way. Show both side by side: the manual steps and the one command.
3. **Playful UI**: let the visitor pick a command or a flag and see the output change, or replay the recording at their own pace.
4. **Proof**: downloads, stars, and teams or projects that use it in their workflow.
5. **Objections**: supported platforms, install methods, what it changes on the machine, whether it sends data anywhere.
6. **CTA**: the install command with a copy button, per platform.

## Web app or SaaS

The visitor is weighing whether signing up is worth their time.

1. **Demo**: the product UI doing its main task. A live sample the visitor can click through, without signing up, beats a video. Use a recorded flow when a live sample is not possible.
2. **Differentiator**: the job done faster, cheaper or with fewer tools than the alternatives. Show the result, such as the report, the design or the sorted inbox, not only the screens.
3. **Playful UI**: a small interactive version of the core action, such as dropping in a file, typing a prompt or dragging a card, with the product's real response.
4. **Proof**: customer logos, testimonials with name and role, case studies with numbers, review site ratings.
5. **Objections**: pricing (show it or link to it), free trial terms, data privacy and security, integrations, migration from the alternative.
6. **CTA**: "Start free" or "Try it", with what the visitor does not need next to it, such as "No credit card".

## Mobile or desktop app

The visitor wants to see the app on their device before installing.

1. **Demo**: the app in a device frame, animated through its main flow. Use real screens from the current version.
2. **Differentiator**: what the app does that the built-in or popular alternative does not.
3. **Playful UI**: a tappable or scrollable mockup of the app, or an animation that follows the visitor's scroll through the main flow.
4. **Proof**: store ratings and review counts, download counts, editorial features, press quotes.
5. **Objections**: supported platforms and OS versions, price and in-app purchases, offline use, privacy (what data it collects).
6. **CTA**: official store badges for each platform. Detect the visitor's platform and show its badge first.

## API or platform

The visitor is a developer or a technical buyer judging integration cost.

1. **Demo**: a request and its real response, in two or three languages the visitor can switch between. Add a live "send request" button with a sandbox key when possible.
2. **Differentiator**: latency, price per call, coverage, limits or reliability, compared with named alternatives.
3. **Playful UI**: let the visitor change a parameter and see the response change.
4. **Proof**: customer logos, request volume, uptime history with a link to the status page.
5. **Objections**: pricing and limits, SLA, data handling and compliance, SDK support, what happens on outage.
6. **CTA**: "Get an API key", with the free tier stated next to it.

## Physical product or hardware

The visitor cannot touch the product, so the page has to stand in for it.

1. **Demo**: the product in use, in photos or video from real use, at real scale. Show the effect, such as the clean floor or the quiet room, not only the object.
2. **Differentiator**: specs that matter to the visitor, compared with the products they would otherwise buy. Turn specs into results: "12 hours of use" instead of "5000 mAh".
3. **Playful UI**: a 360 degree view, an exploded view that assembles on scroll, a color or size picker that updates the photo.
4. **Proof**: ratings and review counts, press, units sold, certifications.
5. **Objections**: price, shipping time and regions, warranty, returns, what is in the box, compatibility.
6. **CTA**: "Buy" or "Pre-order" with the price, the shipping estimate and the return policy next to it.

## Service, course or content

The visitor is buying an outcome from people, not software.

1. **Demo**: a sample of the work: a free lesson, a past project, a before and after, a sample chapter.
2. **Differentiator**: the method, the results and the people, compared with doing it alone or with a typical provider.
3. **Playful UI**: a short quiz or calculator that shows the visitor their own case, such as the time they would save or the plan that fits them.
4. **Proof**: results from past clients or students with names and permission, numbers, credentials of the people behind it.
5. **Objections**: price, time commitment, what is included, refund policy, what happens after.
6. **CTA**: "Book a call", "Enroll" or "Get the free sample", with the next step described.

## Other kinds

For a product that fits none of the kinds above, answer the same six questions:

1. What demo shows its effect?
2. What does it do better than the named alternative?
3. What interaction lets the visitor try the idea?
4. What proof exists?
5. What stops a visitor from starting?
6. What is the first step?
